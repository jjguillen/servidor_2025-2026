# 🌦️ Proyecto: **AgroClima – Registro climático y sanidad vegetal**

## 🎯 Objetivo general

Crear una aplicación web para registrar y analizar variables climáticas (temperatura, humedad, precipitaciones, etc.) junto con incidencias de plagas o enfermedades vegetales, de forma que los agricultores o técnicos puedan **detectar patrones** entre el clima y la aparición de problemas sanitarios en los cultivos.

---

## 🧩 Funcionalidades principales

### 👤 Roles de usuario

* **Administrador**: gestiona usuarios y puede ver todos los registros.
* **Técnico agrícola / agricultor**: registra datos de clima y sanidad en sus parcelas.

### 🌡️ Módulo de datos climáticos

* CRUD de registros diarios con:

  * Fecha
  * Temperatura media (°C)
  * Humedad relativa (%)
  * Precipitación (mm)
  * Velocidad del viento (opcional)
  * Ubicación (parcela o coordenadas)
* Visualización en **gráficas temporales** (por ejemplo, temperatura y humedad a lo largo del mes).
* Filtros por fecha y parcela.

### 🐛 Módulo de sanidad vegetal

* CRUD de incidencias de plagas/enfermedades:

  * Fecha
  * Tipo (pulgón, mildiu, roya, etc.)
  * Severidad (leve, moderada, grave)
  * Cultivo afectado
  * Observaciones
  * Foto opcional (imagen del daño)
* Asociación con el registro climático más cercano en fecha o ubicación.

### 📊 Módulo de análisis

* Página con gráficas comparativas:

  * Temperatura / humedad frente a número de incidencias.
  * Mapa de calor de aparición de plagas.
* Posible uso de **Chart.js**, **Laravel Charts** o **ApexCharts**.
* Exportación de informes en PDF.

### 🔔 Notificaciones y alertas

* Envío de notificaciones cuando:

  * Se detecta una correlación peligrosa (por ejemplo, alta humedad y temperatura → riesgo de mildiu).
* Esto puede implementarse como un **Job en cola** que revise condiciones una vez al día.

## 🧱 Modelo de datos (Eloquent)

Relaciones principales:

```
User ───< Parcela ───< RegistroClimatico
       └──< IncidenciaSanitaria
```

**User**

* id
* nombre
* email
* rol

**Parcela**

* id
* user_id
* nombre
* latitud
* longitud

**RegistroClimatico**

* id
* parcela_id
* fecha
* temperatura
* humedad
* precipitacion
* viento

**IncidenciaSanitaria**

* id
* parcela_id
* fecha
* tipo
* severidad
* cultivo
* observaciones
* imagen (nullable)

## 🔄 Ejemplo de relación Eloquent

```php
class Parcela extends Model
{
    public function registrosClimaticos()
    {
        return $this->hasMany(RegistroClimatico::class);
    }

    public function incidencias()
    {
        return $this->hasMany(IncidenciaSanitaria::class);
    }
}
```

```php
class RegistroClimatico extends Model
{
    public function parcela()
    {
        return $this->belongsTo(Parcela::class);
    }
}
```

## 💡 API externa opcional (nivel avanzado)

Para dar más realismo, se puede integrar una **API meteorológica pública** (Open-Meteo, WeatherAPI, etc.) que permita:

* Obtener automáticamente datos climáticos según la ubicación de la parcela.
* Guardarlos en `RegistroClimatico` con un botón tipo “Actualizar datos”.

Ejemplo de llamada:

```php
$response = Http::get('https://api.open-meteo.com/v1/forecast', [
    'latitude' => $parcela->latitud,
    'longitude' => $parcela->longitud,
    'daily' => 'temperature_2m_max,precipitation_sum',
]);
```
